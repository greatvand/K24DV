Linux System Administration Lab
— Night Shift Maintenance Drill

Day 9 Assignment Enterprise Scenario Solo Lab
Your role: Junior Linux System Administrator at NovaTech Solutions.
Situation: It is 11 PM. The senior admin is unreachable. You must run tonight's scheduled maintenance tasks on the company's internal servers — all from a single terminal session. The tasks include connectivity checks, log collection, and a long-running backup that must survive even if your terminal accidentally closes.

Concepts covered in this lab

Background jobs ( & )Running tasks without blocking the terminal
jobs, fg, bgMonitoring and switching job states
Ctrl+Z / suspendPausing a foreground process
kill %nTerminating specific jobs by number
wait + tput belBlocking until all jobs finish, then alerting
nohupKeeping a process alive after logout
Redirection ( >, >> )Saving command output to log files
Pipes ( | ) & wcCounting and filtering command output

Mission tasks — complete in order

Phase 1
Connectivity verification
Background jobs · Redirection · Pipes

NovaTech's monitoring dashboard is down. You need to manually verify that three critical servers — google.com, bing.com, and yahoo.com — are reachable. The checks must run simultaneously so the report is ready quickly.

1.1Launch a ping of 25 packets to each of the three hosts as background jobs, redirecting each output to a separate log file: server1.log, server2.log, server3.log.
1.2Immediately run jobs to confirm all three are running. Take note of their job numbers.
1.3While they run, use another command to count how many lines are currently in server1.log using a pipe. (Hint: the file grows in real time.)
1.4Use wait combined with tput bel and an echo so the terminal beeps and prints Connectivity checks complete! the moment all three jobs finish.
1.5After they finish, display a summary: print the last 3 lines of each log file to confirm packets were received.
💡 Use ping -c 25 google.com > server1.log & · jobs · cat server1.log | wc -l · wait; tput bel; echo "..." · tail -3 server1.log
Phase 2
Handling an urgent interruption
Suspend · bg · fg · kill

Midway through running a new long connectivity test (ping -c 100 bing.com), you get an urgent Slack message asking you to check a different server immediately. You cannot cancel the test — you just need to pause it.

2.1Start ping -c 100 bing.com > /dev/null in the foreground (no &).
2.2Suspend it without killing it. Run jobs and write down what status is shown next to the job.
2.3Simulate attending to the urgent task by running: echo 'Urgent check done' and ping -c 3 google.com.
2.4Resume the suspended ping in the background so it continues while you move to the next task.
2.5Run jobs again — describe in one sentence what changed in the status output.
2.6You decide this test is taking too long. Bring it to the foreground and cancel it. Then confirm with jobs that no jobs remain.
💡 Use Ctrl+Z · bg %1 · fg %1 · Ctrl+C · jobs
Phase 3
Multi-server load simulation
Multiple jobs · kill %n · jobs

You need to run load tests against four internal endpoints simultaneously. Midway through, one endpoint reports back as unresponsive — you must kill only that job without disturbing the others.

3.1Launch four background ping jobs (use google.com, bing.com, yahoo.com, github.com) each sending 50 packets to /dev/null.
3.2Run jobs and identify which job number corresponds to yahoo.com.
3.3Kill only the yahoo.com job using its job number.
3.4Run jobs again. Do the remaining job numbers shift? Write down your observation.
3.5Let the remaining three jobs finish naturally. Use a single command that waits for all of them and then prints Load test complete.
💡 Use & × 4 · jobs · kill %n · wait; echo "..."
Phase 4
The overnight backup
nohup · ps · nohup.out

The final task is a long backup simulation that will take hours. You cannot keep your terminal open all night. The process must keep running even after you close the session, and you need to be able to check its progress when you return in the morning.

4.1Start the backup simulation using nohup: run ping -c 50 google.com as a background job that is immune to hangups. Note the PID printed in the terminal.
4.2Verify it is running by checking for its PID using ps.
4.3Close your current terminal and open a brand new terminal window. This simulates logging out and back in.
4.4In the new terminal, confirm the process is still running by checking its PID with ps.
4.5Read the output the process has written so far using the correct file.
4.6Count how many lines of output the backup job has produced so far using a pipe.
💡 Use nohup ping -c 50 google.com & · ps <pid> · cat nohup.out · cat nohup.out | wc -l
⭐ Bonus challenge

After Phase 1 is complete, write a single pipeline command that searches all three log files for the word transmitted and prints only those lines — without opening the files one by one. Then count how many total lines matched across all files.
