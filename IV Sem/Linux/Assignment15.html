DevOps

1 — The broken deployment pipeline

E-commerce startup, 3-person engineering team

What happened

Every time a developer pushes code, a deploy script runs on the server. One Friday night, a junior dev pushed broken code. The site went down for 40 minutes because nobody noticed — the deploy script ran, crashed silently, but the old process had already been killed.

Your task

Write a deploy script that: (1) pulls the latest code with git pull, (2) runs the build command npm run build, and (3) only restarts the app with systemctl restart myapp if both previous steps succeeded. If any step fails, print exactly which step failed, log it with a timestamp to deploy.log, and exit with a non-zero code — leaving the running app untouched.

exit codes if/else chaining logging date
if ! git pull; then echo "Step 1 failed" | tee -a deploy.log; exit 1; fi Then repeat for npm run build. Only reach systemctl if both pass. Use $(date '+%Y-%m-%d %H:%M:%S') to prefix log lines.

3 — The SSL certificate time bomb

SaaS company, B2B product

What happened

A company's SSL certificate expired at 3am on a Tuesday. Every customer's browser showed a scary security warning. Revenue dropped to zero for 6 hours. The certificate had been auto-renewing fine for 2 years — until it didn't.

Your task

Write a script that accepts a domain name as $1. Use openssl to check when the SSL certificate expires. If it expires in more than 30 days, print "OK". If between 30 and 7 days, print "WARNING: expires in N days". If under 7 days, print "CRITICAL" and exit with code 2. If the domain can't be reached, handle that case explicitly.

exit codes if/elif/else openssl $1 argument
expiry=$(echo | openssl s_client -connect "$1":443 2>/dev/null | openssl x509 -noout -enddate | cut -d= -f2) expiry_epoch=$(date -d "$expiry" +%s) days_left=$(( (expiry_epoch - $(date +%s)) / 86400 ))

4 — The runaway Docker host

Agency running 30+ client projects on one server

What happened

An agency ran dozens of Docker containers for client preview environments. Developers would spin up containers for demos and forget about them. Over 6 months, 200+ stopped containers and dangling images accumulated, filling up the disk and eventually crashing the host.

Your task

Write a cleanup script that: (1) lists all stopped containers and removes them, counting how many were deleted, (2) removes all dangling images (images with no tag), (3) prints a before/after disk usage comparison using df. The script should ask for confirmation ("Are you sure? y/n") before doing anything destructive.

docker read / confirmation loops command substitution
read -p "Are you sure? (y/n): " confirm [ "$confirm" != "y" ] && exit 0 stopped=$(docker ps -aq -f status=exited) Count with: echo "$stopped" | grep -c . Remove with: docker rm $stopped

5 — The 50-user onboarding nightmare

University IT department, start of academic year

What happened

Every September, the IT team at a university manually creates Linux accounts for 200+ new students. Each account needs a username, a home directory, and a temporary password. Last year it took 3 people an entire day. Half the accounts had typos.

Your task

You are given a file students.txt where each line is firstname,lastname,studentid. Write a script that reads each line, generates a username as firstname_studentid (lowercase), checks if the user already exists, creates the account if not, and logs either "Created: username" or "Skipped: username (already exists)" to onboarding.log.

while read IFS / field splitting id / useradd string manipulation
while IFS=',' read -r first last id; do username=$(echo "${first}_${id}" | tr '[:upper:]' '[:lower:]') if id "$username" &>/dev/null; then echo "Skipped: $username" else useradd "$username"; echo "Created: $username"; fi done < students.txt

Database / Backup

7 — The database backup that ate the disk

Fintech startup, regulated environment

What happened

A startup had a cron job backing up their Postgres database every day to /backups/. Nobody set up any retention policy. After 14 months, backups filled the disk, the database crashed writing new data, and the app went down on a Friday before a bank holiday.

Your task

Write a backup script that dumps the database to /backups/db_YYYY-MM-DD.sql, then deletes any backup files older than 7 days. After cleanup, count how many backup files remain and print "Backup complete. X backups retained." If the dump command fails, do not delete old backups — exit immediately with an error.

exit codes find date formatting conditional logic
filename="db_$(date +%F).sql" if ! pg_dump mydb > "/backups/$filename"; then echo "Dump failed!"; exit 1; fi find /backups -name "db_*.sql" -mtime +7 -delete count=$(ls /backups/db_*.sql | wc -l)

8 — The multi-server morning check

IT admin, small business with 8 branch offices

What happened

An IT admin is responsible for 8 servers across different branch offices. Every morning he manually SSH-es into each one to check disk space, memory, and whether key services are running — a task that takes 30 minutes and is often skipped.

Your task

Write a script that reads server IPs from a file servers.txt (one IP per line). For each server, SSH in and check: (1) disk usage on /, (2) whether nginx is running. Print a summary line per server: [192.168.x.x] Disk: 74% | nginx: UP. If SSH to a server fails, mark it as UNREACHABLE and continue to the next.

while read ssh exit codes remote commands
ssh -o ConnectTimeout=5 "$ip" "df / | awk 'NR==2{print \$5}'" 2>/dev/null If ssh fails, $? will be non-zero — use if ! ssh ...; then echo "UNREACHABLE"; continue; fi The continue keyword skips to the next loop iteration.
Security / Audit

9 — The GDPR breach nobody spotted

Healthcare clinic, compliance audit

What happened

During a GDPR audit, a clinic discovered that files containing patient data (any file with "patient" in the name) had been placed in a world-readable public web directory /var/www/html by mistake. Nobody had checked file permissions in 2 years.

Your task

Write a script that recursively searches /var/www/html for any file whose name contains "patient" (case-insensitive). For each match: print the file path and its current permissions, fix the permissions to 600 (owner read/write only), and append the finding to an audit report audit.log with a timestamp. Print a final count of files fixed.

find chmod stat while read / loops
find /var/www/html -iname "*patient*" -type f | while read -r filepath; do perms=$(stat -c '%a' "$filepath") echo "$(date) FIXED: $filepath (was $perms)" >> audit.log chmod 600 "$filepath" ((count++)) done

10 — The test suite that lied

Product team shipping mobile app updates weekly

What happened

A team had 5 test scripts: test_auth.sh, test_api.sh, test_db.sh, test_ui.sh, test_payments.sh. Their pipeline ran them all and reported "passed" — because someone had written it with ; between commands instead of &&, so failures were silently ignored.

Your task

Write a test runner script that executes each test_*.sh file in a directory. Track which tests passed and which failed based on exit codes. At the end, print a full summary table with pass/fail status per test. If any single test failed, exit the whole script with code 1 (so the CI pipeline correctly marks the build as broken). Never stop early — always run all tests.

exit codes for loop arrays final exit strategy
failed=0 for test in test_*.sh; do if bash "$test"; then results+=("PASS: $test") else results+=("FAIL: $test"); failed=1; fi done Print ${results[@]} in a loop, then exit $failed
