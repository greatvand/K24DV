3 Phase 2 – Parallel Feature Development

Backend Dev A and Backend Dev B work simultaneously on separate branches. This simulates real-world parallel development.

Step 4 Mehak (Backend Dev A)

Implement add_task() Feature

  • Create and switch to branch: feature/add-task
  • Add the following function to tasks.py:
def add_task(title, priority="medium"): global _next_id if priority not in ["high", "medium", "low"]: print("❌ Priority must be: high, medium, or low") return task = {"id": _next_id, "title": title, "priority": priority, "done": False} tasks.append(task) _next_id += 1 print(f"✅ Task added: [{task['id']}] {title} ({priority})")
  • Make at least 2 meaningful commits (e.g., "feat: add add_task with priority support")
  • Push the branch to GitHub
Step 5 Mehak (Backend Dev A)

Implement search_task() Feature

  • Create a new branch: feature/search-task (branch off main, not your previous branch)
  • Add the following function to tasks.py:
def search_task(keyword): results = [t for t in tasks if keyword.lower() in t["title"].lower()] if not results: print(f"🔍 No tasks found matching '{keyword}'") else: print(f"🔍 Found {len(results)} match(es):") for t in results: print(f" [{t['id']}] {t['title']}")
  • Also modify display_tasks() to show a header line: print(f"--- {len(tasks)} Task(s) ---") before the loop — this intentionally creates a merge conflict later
  • Make at least 2 commits. Push the branch.
Step 6 Pathik (Backend Dev B)

Implement delete_task() Feature

  • Add the following function to tasks.py:
def delete_task(task_id): global tasks original_len = len(tasks) tasks = [t for t in tasks if t["id"] != task_id] if len(tasks) < original_len: print(f"🗑️ Task {task_id} deleted.") else: print(f"❌ No task found with ID {task_id}")
  • Make at least 2 commits. Push the branch.
Step 7 Pathik (Backend Dev B)

Implement update_task() Feature

  • Add the following function to tasks.py:
def update_task(task_id, new_title=None, new_priority=None): for t in tasks: if t["id"] == task_id: if new_title: t["title"] = new_title if new_priority in ["high", "medium", "low"]: t["priority"] = new_priority print(f"✏️ Task {task_id} updated.") return print(f"❌ Task {task_id} not found.")
  • Also modify display_tasks() to show done status: change the print line to include [✓] or [ ] prefix based on t['done'] — this intentionally causes a merge conflict with Dev A's change

# test_tasks.py — QA Engineer writes this import tasks def setup_function(): tasks.tasks.clear() tasks._next_id = 1 def test_add_task_creates_entry(): tasks.add_task("Buy groceries", "high") assert len(tasks.tasks) == 1 assert tasks.tasks[0]["title"] == "Buy groceries" def test_add_task_invalid_priority(): tasks.add_task("Read book", "urgent") assert len(tasks.tasks) == 0 def test_delete_task_removes_entry(): tasks.add_task("Write tests", "medium") tasks.delete_task(1) assert len(tasks.tasks) == 0 def test_update_task_changes_title(): tasks.add_task("Old title", "low") tasks.update_task(1, new_title="New title") assert tasks.tasks[0]["title"] == "New title" def test_search_task_finds_match(): tasks.add_task("Deploy to staging", "high") results = [t for t in tasks.tasks if "staging" in t["title"]] assert len(results) == 1

⚠️ Common Mistakes to Avoid
  • Never commit directly to main — branch protection rules will block it anyway
  • Do not merge your own PR — the Team Lead is the only one who merges into main
  • Write meaningful commit messages using the prefix format: feat:, fix:, docs:, test:, chore:
  • Always git pull origin main before branching to avoid unnecessary conflicts
  • Do not delete conflict markers without actually resolving the code — the file must be syntactically valid Python after resolution
  • QA: run pytest locally before pushing — do not push failing tests
  • Tech Writer: link your PR description to the relevant issues using Closes #N
